## 两层验证

在核心库根运行：

```bash
python tools/check_core.py
python tools/check_core.py --scope validation
python tools/check_core.py --scope all
```

默认包测试在 Git checkout 与解包 sdist 中均可运行。资产验收需要完整
仓库的 `validation/`；目录缺失或测试集为空会失败，不静默跳过。
标准 `python -m unittest discover -s tests -p 'test_*.py'` 只发现包测试。
迁移没有删除原有测试或将失败样本改为跳过。

## 发布验证与产物传递

`tools/release_artifacts.py` 只检查和冻结，不构建、不发布：

```bash
python tools/release_artifacts.py check-source --tag v1.0.0
python tools/release_artifacts.py seal --commit <提交SHA> --tag <对应版本标签>
python tools/release_artifacts.py verify --commit <提交SHA> --tag <对应版本标签>
```

本轮治理保持版本1.0.0，这些是命令说明，不表示重发已有版本。分支 CI
不填写标签；标签 CI 必须与包版本相符。`release-manifest.json` 禁止覆盖，
检查产物集合、名称、版本、提交与摘要；PyPI 上传目录只暂存已核验的
wheel/sdist，清单随 GitHub Release 留档。

CI 的 build job 集中构建和封存；现代与3.6在 sdist 中执行包测试，
validation job 在完整仓库独立运行资产测试。两层及旧环境全部通过后，
两个发布 job 才可使用原候选。主分支治理提交不会触发版本发布。
